# 预售系统（定金 / 尾款 / 发货批次）

零依赖（Python 3.11 标准库）实现的预售演示系统：SQLite 存订单与库存，
本地目录放商品演示图，模拟支付适配器支持延迟/重复回执。

## 一条命令启动

```bash
python3 run.py            # 重新播种临界时刻样例，http://localhost:8000
PORT=8123 python3 run.py  # 换端口
KEEP_DATA=1 python3 run.py # 保留现有数据
```

启动后预置的临界时刻样例（时间均相对启动时刻）：

| 样例 | 位置 | 临界行为 |
|---|---|---|
| 尾款窗口刚开启、90 秒后截止 | 活动 A · `PS-…` 待付尾款 | 尾款页显示应付金额与截止时间 |
| 尾款已付 80/160（部分支付） | 活动 A | 剩余 80 元回执**延迟 45 秒**到达 |
| 已付清 | 活动 A | 财务可“配货到批次→发货” |
| 尾款逾期已释放 | 活动 B | 90 元尾款回执延迟 20 秒到达 → **异常款**，不发货 |
| 部分支付后逾期 | 活动 B | 释放时已付 40 元自动挂异常款待退款 |
| 活动已取消 | 活动 C | 取消后迟到的尾款 → 异常款待退款 |

后台每秒推进一次：尾款开窗、投递到期回执、逾期（含 30 秒宽限）释放名额。

## 页面与角色

右上角切换视角（cookie，无鉴权仅作演示）：

- **买家 customer**：下单（占名额、锁定规则版本）、付定金/尾款（可部分支付、可模拟回执延迟、可重放回执）。
- **客服 customer_service**：只能查看订单与库存、在订单页**发起处理请求**，不能改账/退款/审核。
- **财务 finance**：发布新定金规则版本、变更规格、取消活动、配货/发货、审核异常款
  （批准退款 / 核准恢复发货 / 驳回）。

页面：

- **活动页**：库存看板显示 `预留 / 已付 / 释放` 三值（另有退款中、可售），
  订单表分列定金已付、尾款已付、已付合计；规则版本表与批次表。
- **订单页**：定金、尾款、已付合计三个金额块；付款窗口时间轴（定金段/尾款段/当前时刻游标/截止刻度）；
  事件时间线；全部支付回执（含重复标记）与重放入口。
- **异常款队列 `/exceptions`**：释放后迟到款、多付/部分款待退、取消活动后到账。

## 关键业务规则

1. **不超卖**：下单在 `BEGIN IMMEDIATE` 事务内原子“统计占名额订单 + 插入”，名额满即拒绝。
2. **规则版本锁定**：订单行快照定金/尾款金额、时间窗口、宽限与版本号；
   财务之后发布 v2 规则或变更规格，只影响新订单。
3. **支付/释放竞争**：支付与释放都在同一 IMMEDIATE 事务内重读订单行判定状态——
   付款成功（→ paid）的订单释放会跳过；释放后到达的付款绝不入账到订单，
   而是进异常款队列。因此**不可能既退款又发货**。
4. **回执幂等**：`receipt_no` 唯一；重复回执标记为 duplicate 且**不改变原入账**。
5. **部分尾款**：按已付累加，付清前释放则已付部分挂异常款待财务退款；多付部分同样挂账，订单仍正常发货。
6. **取消活动**：未付清订单取消并退款审核；已付清订单合同成立继续配货；取消后新付款进异常款。
7. **发货批次**：按付清先后配货，受批次容量与最早发货时间约束。

## 测试

```bash
python3 -m unittest discover -s/tests   # 或 python3 tests/test_xxx.py
```

- `test_oversell` 40 线程抢 5 名额
- `test_delayed_receipt` 截止前后延迟回执、部分支付释放、多付、定金金额不符
- `test_rule_version` 规则改版/规格变更不影响老订单
- `test_duplicate_payment` 重复回执不重复入账
- `test_payment_release_race` 30 单在截止点并发付款 vs 释放，验证发货/退款集合互斥
- `test_cancel_activity` 取消活动与取消后付款
